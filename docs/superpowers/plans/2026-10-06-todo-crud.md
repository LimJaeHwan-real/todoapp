# Todo 앱 구현 계획

## 1분 요약

**목표:** 기존 Spring Boot 의존성으로 브라우저에서 할일을 조회·등록·수정·삭제한다. 화면은 Thymeleaf, 저장은 MyBatis와 PostgreSQL을 사용한다.

| 기능 | 사용 방법 | 완료 기준 | 실패 처리 |
|---|---|---|---|
| 목록 | 목록 화면 열기 | 최신 등록순 표시 | 빈 목록 안내 |
| 상세 | 할일 선택 | 제목·내용·등록일·수정일 표시 | 없는 대상 안내 |
| 등록 | 제목·내용 입력 후 저장 | 새 ID로 저장 → 상세 이동 | 입력 유지·오류 표시 |
| 수정 | 상세에서 수정 후 저장 | 변경 반영 → 상세 이동 | 입력 오류·없는 대상 안내 |
| 삭제 | 상세에서 삭제 확인 | 해당 항목 삭제 → 목록 이동 | 없는 대상 안내 |

- **제외:** 로그인, 완료 체크, 검색, 페이징, 배포.
- **유지:** 책의 계층 구분, 기존 기술·버전, 관련 없는 사용자 변경.
- **보호:** 로컬 `application.properties` 내용과 `.env` 계열은 커밋·푸시하지 않는다.
- **승인:** 이 문서 수정은 코드 구현 승인이 아니다. 구현은 승인된 범위에서 진행한다. JSON API 전환은 계획 조정 후 진행한다.

## 기술 상세 — 구현 참고

### 1. 기존 의존성 활용

Java **21**, Spring Boot **4.0.9-SNAPSHOT**, MyBatis **4.0.1** 및 `build.gradle`의 적용 범위를 유지한다. 생략된 버전은 기존 의존성 관리에 맡긴다. 아래는 선언된 의존성 10종이다.

| 의존성 | 적용할 코드·파일 | 확인 기준 |
|---|---|---|
| `spring-boot-starter-thymeleaf` | 템플릿의 `th:each/text/object/field/errors/action` | 실제 HTML·입력 유지·이스케이프 |
| `spring-boot-starter-webmvc` | `TodoController`: `@Controller`, GET/POST 매핑, 폼·모델 처리. `TodoExceptionHandler`: 예외 처리 | 경로·리다이렉트·오류 응답 |
| `mybatis-spring-boot-starter:4.0.1` | `TodoMapper`의 `@Mapper` + XML SQL·행 매핑 | 정렬·필드 매핑·생성 ID·변경 행 수 |
| `lombok` | `Todo`: `@Getter`, `@AllArgsConstructor`, `final`. 주입 대상 클래스: `@RequiredArgsConstructor`. 폼·DB 행: 필요한 getter/setter | 메인·테스트 코드 생성·컴파일 |
| `spring-boot-devtools` | 로컬 `bootRun`의 변경 후 재시작 | 개발 중 변경 반영 |
| `postgresql` | 환경 설정 → Spring `DataSource` → MyBatis 연결 | 실제 PostgreSQL CRUD |
| `spring-boot-starter-thymeleaf-test` | `TodoControllerTest`: 템플릿 응답 검사 | 목록·상세·폼·오류 HTML |
| `spring-boot-starter-webmvc-test` | 같은 테스트의 `@WebMvcTest`, `MockMvc`, `@MockitoBean` | DB 없이 요청·응답 검증 |
| `mybatis-spring-boot-starter-test:4.0.1` | `TodoRepositoryImplTest`: `@MybatisTest`, `@Import`, `@AutoConfigureTestDatabase(replace = NONE)` | 검증용 PostgreSQL 사용·테스트 롤백 |
| `junit-platform-launcher` | 기존 Gradle `useJUnitPlatform()` | 테스트 발견·실행 건수·결과 |

- Spring Boot 항목의 그룹은 `org.springframework.boot`, MyBatis는 `org.mybatis.spring.boot`, 나머지는 기존 `build.gradle` 선언을 따른다.
- Lombok은 메인·테스트의 기존 어노테이션 처리기를 사용한다. DevTools·테스트 런처는 업무 코드에서 직접 호출하지 않는다.
- `TodoServiceImpl`: `@Service`, `@Transactional` 사용. 조회는 `readOnly = true`, 쓰기는 일반 트랜잭션.
- Validation 스타터는 추가하지 않는다. 도메인에서 제목을 검사하고, 컨트롤러의 `BindingResult.rejectValue("title", ...)`로 폼 오류를 표시한다. 다른 예외를 제목 오류로 처리하지 않는다.
- 테스트 패키지는 **Spring Boot 4** 기준: `org.springframework.boot.webmvc.test.autoconfigure.WebMvcTest`, JDBC 테스트 어노테이션도 Boot 4 패키지 사용. MyBatis 예제의 구버전 패키지를 복사하지 않는다.
- 새 의존성·아키텍처 경계 변경은 별도 승인 대상이다.

### 2. 계층과 파일

Java 기준 경로: `src/main/java/com/example/todoapp/todo/`.

| 계층 | 파일·책임 |
|---|---|
| 애플리케이션 | `application/controller/{TodoController,TodoExceptionHandler}.java`: 요청·오류. `application/form/TodoForm.java`: 입력. `application/view/TodoView.java`: 출력 |
| 도메인 | `domain/model/Todo.java`: 객체·규칙. `domain/service/{TodoService,TodoServiceImpl,TodoNotFoundException}.java`: 기능·트랜잭션·대상 없음. `domain/repository/TodoRepository.java`: 저장 계약 |
| 인프라 | `infrastructure/mapper/{TodoMapper,TodoRow}.java`: SQL 연결·DB 행. `infrastructure/repository/TodoRepositoryImpl.java`: 매퍼 호출·도메인 변환 |

- 의존 방향: **애플리케이션 → 도메인, 인프라 → 도메인**. 호출은 컨트롤러 → 서비스 → 저장소 인터페이스; 구현체는 Spring이 연결한다.
- `Todo`는 Lombok만 허용하며 Spring·MyBatis·HTTP에 의존하지 않는다. 도메인에 컨트롤러·폼·뷰·SQL을 넣지 않는다. 서비스는 매퍼를 직접 참조하지 않는다.
- 화면 흐름: `TodoForm` → 서비스 → `Todo` → `TodoView`. 도메인 객체를 폼에 직접 연결하지 않는다.
- 리소스: `src/main/resources/mybatis/TodoMapper.xml`, `templates/todos/{list,detail,form}.html`, `templates/error/{400,404,503}.html`.
- 테스트: `src/test/java/com/example/todoapp/todo/` 아래 `domain/{model,service}`, `application/controller`, `infrastructure/repository`. 기존 `TodoappApplicationTests`도 검증 DB로 점검한다.

### 3. 데이터·요청 규칙

| 항목 | 규칙 |
|---|---|
| 테이블·ID | `todos(id, todo, detail, created_at, updated_at)` 유지. `serial` → `Integer`, DB `todo` → Java `title` |
| 입력 | 제목: 앞뒤 공백 제거 후 1~255자. 내용: 선택. 생성·변경 규칙은 도메인 메서드에서 검사 |
| 날짜 | `LocalDateTime`, 단일 서버 시간 기준. 등록 시 두 날짜 설정; 수정 시 ID·등록일 유지; 조회 시 날짜 변경 금지 |
| SQL | `#{...}` 바인딩, `resultMap` 필드 매핑, `useGeneratedKeys`·`keyProperty="id"`로 생성 ID 회수 |
| 정렬·존재 확인 | `created_at DESC NULLS LAST, id DESC`. 수정·삭제 행 수가 0이면 대상 없음 |
| 응답 | 잘못된 ID 400, 없는 대상 404, DB 연결 실패 503. 인증정보·내부 SQL 오류 노출 금지 |
| 화면 | 저장 후 리다이렉트, 삭제는 확인 후 POST만 사용, 입력 내용 이스케이프 |

| 기능 | 경로 |
|---|---|
| 목록·상세 | `GET /todos`, `GET /todos/{id}` |
| 등록 | `GET /todos/new`, `POST /todos` |
| 수정 | `GET /todos/{id}/edit`, `POST /todos/{id}/edit` |
| 삭제 | `POST /todos/{id}/delete` |

### 4. 설정·데이터 보호

- 기존 사용자 변경 보존. 준비 단계에서 `.gitignore`에 `**/application.properties`, `**/.env`, `**/.env.*` 추가.
- `git rm --cached -- src/main/resources/application.properties`로 **추적만 해제**, 로컬 내용 보존. 삭제 기록만 커밋하며 내용 추가·수정·재등록·`git add -f` 금지.
- 공유 설정: 인증정보 없는 `src/main/resources/application.properties.example`. 환경 변수 참조 또는 로컬 값으로 연결하며 테스트에도 비밀정보를 하드코딩하지 않는다.
- `schema.sql`: `DROP TABLE` 제거 → `CREATE TABLE IF NOT EXISTS`. 초기화 기본 `never`, 필요한 로컬 환경에서만 명시적으로 활성화. 기존 테이블 구조는 자동 변경하지 않는다.
- 추적 해제 후에도 과거 이력은 남는다. 이력 재작성·강제 푸시는 별도 승인 없이 수행하지 않는다.

### 5. 구현 순서

각 단계: **테스트 작성 → 구현 → 검증 → 변경 검토 → 해당 파일만 커밋**. 필요한 저장소 메서드·화면은 기능별로 추가한다.

| 단계 | 구현 범위 | 완료 기준 | 예정 커밋 |
|---|---|---|---|
| 0. 준비 | 제외 규칙·설정 예시·안전한 스키마·검증 설정 | 로컬 설정 보존·추적 해제, DB/테스트 설정·개발 도구 확인 | `build(database): 로컬 설정을 Git에서 제외하고 안전한 DB 초기화를 구성한다` |
| 1. 목록 | 객체·서비스·저장소·매퍼·컨트롤러·목록 화면 | 빈 목록·다중 항목·정렬·DB 실패 | `feat(todo): 할일 목록을 조회한다` |
| 2. 상세 | ID 조회·상세 화면·예외 처리 | 정상·없는 대상·잘못된 ID | `feat(todo): 기본키로 할일 상세 정보를 조회한다` |
| 3. 등록 | 생성 규칙·저장 SQL·폼·등록 화면 | 생성 ID·날짜·빈 제목·255자 경계·공백·입력 오류 | `feat(todo): 새로운 할일을 등록한다` |
| 4. 수정 | 변경 규칙·갱신 SQL·수정 폼 | 변경 반영·등록일 유지·수정일 갱신·실패 처리 | `feat(todo): 등록된 할일을 수정한다` |
| 5. 삭제 | 삭제 기능·SQL·확인 버튼 | 대상만 삭제·다른 항목 유지·없는 대상·GET 삭제 불가 | `feat(todo): 등록된 할일을 삭제한다` |

### 6. 검증·완료 기준

- [ ] 단계별 `./gradlew.bat test --tests '<대상 테스트 클래스>'`: 도메인·서비스·MVC·실제 템플릿 응답 검증. 웹 테스트는 서비스 대체로 DB와 분리.
- [ ] 별도 검증용 PostgreSQL: DB·쓰기 범위 확인 후 SQL·매핑·생성 ID·변경 행 수 검증. 기존 사용자 데이터 접근 금지.
- [ ] 최종 `./gradlew.bat test`, `./gradlew.bat build`, 브라우저 등록 → 목록 → 상세 → 수정 → 삭제, 일반 재시작 후 데이터 유지 확인.
- [ ] 의존성 표와 코드·테스트 대조. DevTools 개발 편의 검증은 CRUD 검증과 구분.
- [ ] Git 점검: `git ls-files -- src/main/resources/application.properties`는 빈 결과, `git check-ignore -v -- src/main/resources/application.properties`는 제외 규칙 확인, 로컬 파일 존재 확인.
- [ ] 커밋·푸시 전 비밀정보·대상 경로 확인 및 `git diff --staged --check`. 설정 내용·`.env` 추가/수정/재등록이 스테이징되면 중단. 푸시는 별도 요청 시 수행.

실패는 해당 기능 범위에서 수정한다. DB·브라우저 검증이 불가능하면 **미검증**, 전체 완료로 처리하지 않는다.
