# Todo 앱 구현 계획

## 1분 요약

Spring Boot와 PostgreSQL로 할일 관리 기능 5개를 만든다. **기본안은 브라우저 화면(Thymeleaf)**이며, JSON API를 원하면 화면·요청 처리 부분만 계획을 조정한다. 책에 맞춰 화면·컨트롤러·폼은 애플리케이션, 서비스와 할일 객체는 도메인, DB 매퍼와 저장소 구현은 인프라 계층에 둔다.

| 기능 | 사용 방법 | 완료 기준 | 실패 처리 |
|---|---|---|---|
| 목록보기 | 할일 목록 화면을 연다 | 저장된 할일을 최신 등록순으로 표시한다 | 등록된 항목이 없으면 빈 목록 안내를 표시한다 |
| 상세보기 | 목록에서 할일을 선택한다 | 기본키로 찾은 제목·내용·등록일·수정일을 표시한다 | 없어진 할일이면 찾을 수 없다는 안내를 표시한다 |
| 등록 | 제목과 내용을 입력하고 저장한다 | 새 기본키로 저장되고 상세 화면으로 이동한다 | 제목이 잘못되면 입력을 유지하고 오류를 표시한다 |
| 업데이트 | 상세 화면에서 수정하고 저장한다 | 제목·내용·수정일이 바뀌고 상세 화면에 반영된다 | 입력 오류는 폼에 표시하고, 대상이 없으면 찾을 수 없다고 안내한다 |
| 삭제 | 상세 화면에서 삭제를 확인한다 | 해당 할일만 삭제되고 목록으로 이동한다 | 대상이 없으면 찾을 수 없다고 안내한다 |

로그인, 완료 체크, 검색, 페이징, 배포는 이번 범위에서 제외한다. **`application.properties`는 로컬 전용으로 유지하고, 파일 내용을 앞으로 커밋·푸시하지 않는다.** 이 문서는 전체 CRUD 구현을 위한 계획이며, 구현은 사용자가 승인한 범위에서 진행한다.

## 기술 상세 — 구현 참고

### 현재 상태와 먼저 정리할 사항

- Java 21, Spring Boot `4.0.9-SNAPSHOT`, MyBatis `4.0.1`, Thymeleaf, PostgreSQL 드라이버가 이미 포함되어 있다. 기존 기술과 버전을 유지한다.
- 구현은 `build.gradle`에 이미 선언된 의존성을 우선 사용한다. Lombok은 `compileOnly`·`annotationProcessor`, 테스트에는 `testCompileOnly`·`testAnnotationProcessor`가 설정되어 있어 추가 설치 없이 코드 생성에 사용한다.

| 기존 의존성 | 구현에 사용할 용도 |
|---|---|
| Thymeleaf · Web MVC | 뷰 템플릿, 컨트롤러의 요청·응답 처리 |
| MyBatis · PostgreSQL 드라이버 | O/R 매퍼, SQL 실행, PostgreSQL 연결 |
| Lombok | `Todo`의 `@Getter`·`@AllArgsConstructor`, 서비스·컨트롤러·저장소 구현의 `@RequiredArgsConstructor`를 통한 생성자 주입 |
| 기존 테스트 의존성 | 도메인·서비스 단위 검증, MVC 요청·응답 검증 |

- 현재 테이블은 `todos(id, todo, detail, created_at, updated_at)`이다. 스키마와 이름을 유지하고 Java의 `title`을 DB의 `todo`에 연결한다.
- 사용자 변경인 `application.properties`와 미추적 `schema.sql`은 현재 그대로 보존한다. 구현 시 로컬 설정 파일은 유지하고, 필요한 초기화 설정만 로컬에서 조정한다.
- 첫 준비 단계에서 `.gitignore`에 `**/application.properties`, `**/.env`, `**/.env.*`를 추가한다. 이미 추적 중인 파일은 `git rm --cached -- src/main/resources/application.properties`로 추적만 해제하고 로컬 파일·내용은 보존한다. 추적 해제용 삭제 기록만 커밋에 포함하고, 해당 파일 내용의 추가·수정·재등록 및 강제 추가(`git add -f`)는 금지한다.
- 공유 설정은 실제 인증정보가 없는 `src/main/resources/application.properties.example`로 제공한다. 개발자는 이를 로컬 `application.properties`로 복사하고 환경 변수 참조 또는 로컬 값으로 설정한다. 검증 설정에도 인증정보를 하드코딩하지 않는다.
- 첫 커밋에 포함된 파일은 과거 Git 이력과 GitHub 과거 버전에 남아 있다. 추적 해제는 이후 버전의 업로드를 막는 조치다. 과거 이력의 완전 제거는 이력 재작성과 강제 푸시가 필요한 별도 작업으로, 명시적 승인 없이 수행하지 않는다.
- `schema.sql`의 `DROP TABLE`을 제거하고 `CREATE TABLE IF NOT EXISTS`로 바꾼다. 자동 초기화는 기본 `never`, 필요한 로컬 환경에서만 명시적으로 켠다. 기존 테이블의 구조 변경까지 자동 처리하는 방식은 아니다.

### 계층과 파일 역할

기본 패키지는 `com.example.todoapp.todo`로 한다. **계층 배치는 사용자가 제시한 책의 구분을 따른다.** 할일 객체의 생성·변경 규칙은 도메인 객체에서 지킨다.

| 계층 | 책의 구성요소 | 주요 파일·폴더와 책임 |
|---|---|---|
| 애플리케이션 | 뷰, 컨트롤러, 폼 | `application/controller/TodoController.java`, `TodoExceptionHandler.java`: 요청·응답·오류 안내. `application/form/TodoForm.java`: 입력값 수신. `application/view/TodoView.java`와 Thymeleaf 템플릿: 화면 출력 |
| 도메인 | 서비스, ServiceImpl, Domain Object, 리포지토리 | `domain/service/TodoService.java`: 기능 인터페이스. `TodoServiceImpl.java`: 기능 처리·트랜잭션. `TodoNotFoundException.java`: 대상 없음. `domain/model/Todo.java`: 할일 객체·규칙. `domain/repository/TodoRepository.java`: 저장소 인터페이스 |
| 인프라 | O/R 매퍼, RepositoryImpl | `infrastructure/mapper/TodoMapper.java`, `TodoRow.java`, 매퍼 XML: MyBatis SQL·DB 행 매핑. `infrastructure/repository/TodoRepositoryImpl.java`: 저장소 인터페이스 구현·DB 행과 도메인 객체 변환 |

- 의존 방향: 애플리케이션 → 도메인, 인프라 → 도메인. 컨트롤러는 `TodoService`를 호출하고 `TodoServiceImpl`은 `TodoRepository`를 사용한다. 구현체 연결은 Spring이 담당한다.
- 컨트롤러·폼·뷰와 SQL은 도메인에 넣지 않는다. 도메인 객체 `Todo`는 Spring·MyBatis·HTTP에 의존하지 않는다. 도메인의 서비스 구현에는 Spring의 서비스·트랜잭션 선언을 사용하되 컨트롤러나 MyBatis 매퍼를 직접 참조하지 않는다.
- 도메인 객체 `Todo`에는 반복 코드 생성용 Lombok을 허용한다. `@Getter`와 `@AllArgsConstructor`로 기존 getter·전체 필드 생성자를 유지하고 필드는 `final`로 둔다. 할일 생성·변경 규칙은 명시적인 도메인 메서드로 작성한다.
- 도메인 객체를 폼에 직접 연결하지 않는다. 컨트롤러가 `TodoForm`의 제목·내용을 서비스에 전달하고, 조회 결과인 `Todo`를 `TodoView`로 변환해 화면에 전달한다.
- 책의 O/R 매퍼 역할에는 기존 MyBatis를 사용한다. SQL: `src/main/resources/mybatis/TodoMapper.xml`. 뷰는 애플리케이션 계층에 속하지만 Spring Boot의 기본 위치인 `src/main/resources/templates/todos/{list,detail,form}.html` 및 `templates/error/{400,404,503}.html`에 둔다.
- 테스트: `src/test/java/com/example/todoapp/todo/domain/{model,service}`, `application/controller`, `infrastructure/repository`. 기존 `TodoappApplicationTests`는 안전한 검증 DB 설정으로 점검한다.

### 데이터·요청·오류 규칙

- 기본키는 기존 PostgreSQL `serial`에 맞춰 `Integer`를 사용한다. 제목은 앞뒤 공백을 제거한 뒤 1~255자로 제한하고, 상세 내용은 선택 입력으로 둔다.
- 등록 시 등록일·수정일을 채우고, 수정 시 기본키·등록일은 유지한다. 날짜는 기존 `timestamp without time zone`에 맞춰 `LocalDateTime`과 단일 서버 시간 기준을 사용한다.
- 도메인의 생성·변경 메서드에서 제목 규칙을 검사한다. 기존 DB 행을 읽을 때는 등록·수정 메서드를 호출하지 않아 날짜가 바뀌지 않게 한다.
- 도메인 계층의 `TodoServiceImpl`에서 조회는 읽기 전용, 등록·수정·삭제는 쓰기 트랜잭션으로 처리한다. 수정·삭제는 영향받은 행 수를 확인해 사라진 대상을 판별한다.
- SQL 값은 MyBatis `#{...}`로 바인딩하고, 등록 후 생성된 기본키를 회수한다. 정렬은 `created_at DESC NULLS LAST, id DESC`로 고정한다.
- 잘못된 기본키는 400, 없는 대상은 404로 처리한다. DB 연결 실패는 503 안내로 처리하고 인증정보·SQL 내부 오류를 화면에 노출하지 않는다.
- 경로: `GET /todos`, `GET /todos/{id}`, `GET /todos/new`, `POST /todos`, `GET /todos/{id}/edit`, `POST /todos/{id}/edit`, `POST /todos/{id}/delete`.
- 저장 성공 후에는 리다이렉트하여 새로고침 중복 제출을 줄인다. 삭제는 GET 요청으로 실행하지 않고 확인 후 POST로 처리한다. 템플릿은 입력 내용을 이스케이프해 표시한다.

### 기능별 구현·커밋 순서

각 기능은 **관련 테스트 작성 → 구현 → 검증 → 변경 검토 → 필요한 파일만 커밋** 순서로 진행한다. 필요한 저장소 메서드와 화면은 해당 기능을 구현할 때 추가한다.

| 단계 | 구현 범위와 주요 파일 | 완료·검증 기준 | 커밋 메시지 |
|---|---|---|---|
| 0. 안전한 실행 준비 | `.gitignore`, 설정 파일 추적 해제, `application.properties.example`, `schema.sql`, 검증용 설정 | 로컬 파일 보존, Git 추적 해제·제외 규칙·설정 예시 검증, 삭제 구문 제거 | `build(database): 로컬 설정을 Git에서 제외하고 안전한 DB 초기화를 구성한다` |
| 1. 목록보기 | 도메인의 `Todo`, `TodoRepository`, `TodoService`, `TodoServiceImpl`, 인프라의 `TodoRepositoryImpl`·매퍼, 애플리케이션의 컨트롤러·`TodoView`·`list.html` | 빈 목록·여러 항목·정렬·DB 실패 안내 검증 | `feat(todo): 할일 목록을 조회한다` |
| 2. 상세보기 | 도메인 서비스·저장소 인터페이스의 기본키 조회, 인프라 저장소·매퍼 구현, 애플리케이션의 상세 요청·`detail.html`·예외 처리 | 존재하는 대상·없는 대상·잘못된 기본키 검증 | `feat(todo): 기본키로 할일 상세 정보를 조회한다` |
| 3. 등록 | 도메인 생성 규칙·서비스 등록 기능, 인프라 저장 기능, 애플리케이션의 `TodoForm`·등록 요청·`form.html` | 정상 저장·생성 ID·날짜·빈 제목·255자 경계·공백·폼 오류 검증 | `feat(todo): 새로운 할일을 등록한다` |
| 4. 업데이트 | 도메인 변경 규칙·서비스 수정 기능, 인프라 갱신 기능, 애플리케이션 수정 요청·폼 | 제목·내용 변경, 등록일 유지, 수정일 갱신, 입력 오류·없는 대상 검증 | `feat(todo): 등록된 할일을 수정한다` |
| 5. 삭제 | 도메인 서비스 삭제 기능, 인프라 삭제 기능, 애플리케이션 삭제 요청·확인 버튼 | 대상만 삭제, 다른 항목 유지, 없는 대상 처리, GET으로 삭제 불가 검증 | `feat(todo): 등록된 할일을 삭제한다` |

### 검증과 완료 기준

- 단계마다 해당 도메인·서비스·웹 테스트를 `./gradlew.bat test --tests '<대상 테스트 클래스>'`로 실행한다. 웹 테스트는 저장소·서비스를 대체해 DB와 분리한다.
- MyBatis 저장소는 **별도 검증용 PostgreSQL**에서 SQL 실행·생성 ID·필드 매핑·수정 및 삭제 결과를 통합 검증한다. 사용할 DB와 테스트 데이터 쓰기 범위를 확인한 뒤 실행하고, 기존 사용 데이터에는 접근하지 않는다.
- 마지막에는 전체 테스트와 `./gradlew.bat build`, 브라우저의 등록 → 목록 → 상세 → 수정 → 삭제 흐름, 재시작 후 데이터 유지 여부를 확인한다.
- 준비 단계 완료 시 `git ls-files -- src/main/resources/application.properties` 결과가 비어 있는지, `git check-ignore -v -- src/main/resources/application.properties`가 제외 규칙을 찾는지, 로컬 파일이 남아 있는지 확인한다.
- 매 커밋·푸시 전 대상 파일 목록과 비밀정보 여부를 확인한다. `application.properties`와 `.env` 계열 파일의 추가·수정·재등록이 스테이징되어 있으면 중단한다. 공유 예시에도 실제 인증정보가 없어야 한다. `git diff --staged --check`를 실행하고 필요한 파일만 스테이징하며, 푸시는 별도 요청 시 수행한다.
- 실패한 검증은 해당 기능 범위에서 해결한다. 실제 PostgreSQL 또는 브라우저 검증이 불가능하면 **미검증**으로 남기며, 기능 완료로 간주하지 않는다.

계층 설계 기준: 사용자가 제시한 책의 구성. 구현 참고: [Spring Boot DB 초기화](https://docs.spring.io/spring-boot/how-to/data-initialization.html), [MyBatis SQL 매핑](https://mybatis.org/mybatis-3/sqlmap-xml.html).
